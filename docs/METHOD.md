# 방법론

이 저장소의 진짜 자산은 코드가 아니라 이 문서다.
지구과학Ⅰ·Ⅱ 760문항을 처리하며 자리 잡은 공정이고, 과목이 바뀌어도 그대로 쓴다.

---

## 원칙

### 1. 사람과 LLM이 개입하는 지점을 셋으로 줄인다

나머지는 전부 스크립트가 한다. LLM이 PDF를 읽거나 380개 파일을 훑으면 비용이 폭발한다.

| 개입 지점 | 무엇을 보나 | 왜 자동화가 안 되나 |
|---|---|---|
| **크롭 QA** | 대지(contact sheet) 이미지 한 장 | 선지가 잘렸는지는 봐야 안다 |
| **분류 큐** | 애매한 문항 20~30%의 본문 400자 | 개념 판단은 규칙으로 안 된다 |
| **예외 처리** | 리포트의 `attention` 항목 | 새 판형은 늘 처음 본다 |

### 2. LLM은 리포트만 읽는다

모든 명령이 `reports/<step>.json` 하나를 남긴다. `attention` 은 30건에서 자른다.
**이 상한이 없으면 오류가 많은 회차 하나가 컨텍스트를 통째로 태운다.**

### 3. 추측해서 채우지 않는다

정답 3중 대조가 갈리면 비워둔다. 과목 별칭이 안 맞으면 건너뛰고 기록한다.
"아마 이것일 것"으로 채운 값은 **틀렸을 때 아무도 못 찾는다.** 비어 있으면 최소한 보인다.

### 4. 원본은 불변

`sources/` 아래 내려받은 PDF는 어떤 단계도 고치지 않는다.
잘못됐으면 다시 받는다. 원본을 고치기 시작하면 재현이 안 된다.

## 공정

```
download → detect → crop → extract → classify → map → validate → build
```

각 단계는 앞 단계의 산출물만 읽는다. **되돌아가지 않는다.**
문제가 생기면 그 단계를 고쳐서 다시 돌린다.

### 새 과목을 시작할 때의 순서

1. **한 회차만 끝까지 돌린다.** 전체를 돌리기 전에 반드시.
   판형 예외는 과목마다 새로 나오고, 380문항을 다 망친 뒤에 알면 늦다.
2. 대지를 눈으로 본다. 선지가 잘린 것이 하나라도 있으면 크롭부터 고친다.
3. `validate` 의 배점 합·문항 수 불변식이 통과하는지 본다. 여기서 걸리면 추출이 틀린 것이다.
4. 그 다음에 전체를 돌린다.

## 전사 검수 — 2단계 교차 확인

문항 본문을 사람이 읽을 수 있게 만들 때 쓰는 공정이다. 자동 추출만으로는 오독이 남는다.

1. **독립 전사 2회.** 서로의 결과를 보지 않은 상태에서 같은 문항을 각각 전사한다.
2. **판정.** 두 결과가 다른 지점만 모아, 판정자가 **원본 이미지를 다시 보고** 결정한다.
   텍스트만 비교하면 둘 다 같은 방식으로 틀린 경우를 못 잡는다.
3. 판정자가 확신하지 못하면 `status` 를 `scaffold` 로 두고 넘어간다.

> 비용 실측: 문항당 약 65,000토큰. 비용을 좌우한 것은 프로세스 개수가 아니라
> **판정 단계에서 이미지를 얼마나 깊이 다시 확인하느냐**였다.
> 얕게 하면 싸지지만 오독이 남는다.

## 분류 — 하이브리드

```
키워드 사전으로 전체 채점
    ├─ 확신 (최고점 ≥ 0.35, 1·2위 차 ≥ 0.15)  →  자동 확정  (약 70~80%)
    └─ 애매                                    →  LLM 큐로   (약 20~30%)
```

### 키워드 사전은 교육과정에서 자동 생성한다

`gw standards --draft-keywords` 가 성취기준 문장에서 명사구를 뽑아 초안을 만든다.
**사용자가 빈 파일을 마주하면 새 과목을 시작하지 않는다.** 초안이 있어야 손을 댄다.

초안을 다듬을 때 지킬 것:
- 평가 동사(`이해한다`, `설명할 수 있다`, `탐구한다`)는 전부 뺀다. 판정에 방해만 된다.
- 그 단원에만 나오는 말을 넣는다. 여러 단원에 걸치는 말은 점수를 흐린다.
- 교과서 용어와 문항 표현이 다르면 **문항 표현** 쪽을 넣는다.

### LLM이 큐를 판정할 때

`classify_queue.json` 에는 문항당 본문 400자와 후보 성취기준 3개만 들어 있다.
판정 기준은 하나다 — **그 성취기준이 다루는 대상(명사)이 문항에 나오는가.**
학습 활동의 동사가 일치하는지는 묻지 않는다. (이유는 `PITFALLS.md` 5-1)

## 교육과정 매핑 (2015 → 2022 같은 개정 간 이관)

이건 자동화되지 않는다. 실측한 비용은 760문항에 Sonnet 태거 10대 + Opus 감사,
그러고도 1차 결과가 틀려서 130문항을 재검토했다.

> **그래서 매핑은 런타임에 계산하지 않고 데이터로 배포한다.**
> `subjects/<slug>/mapping.json` 이 그 결과물이다. 쓰는 사람은 LLM 비용을 내지 않는다.

새 과목의 매핑을 만들 때:

1. 두 개정의 성취기준을 나란히 놓고 **대상(명사) 기준으로** 후보를 좁힌다.
2. 문항을 배치로 나눠 태깅한다. 배치마다 같은 통제 어휘를 쓴다.
3. **0문항인 성취기준을 반드시 감사한다.** 진짜 없는 것인지, 판정을 잘못한 것인지
   해당 개념의 어휘로 전체 문항 본문을 검색해서 확인한다. 이 감사가 없으면 조용히 틀린다.
4. 대응없음은 `null` 로 명시한다. 조사 안 한 것과 없는 것은 다르다.

## 확장

### 다른 탐구 과목
판형이 같으므로(`tamgu-1q1block`) 새로 필요한 것은 `subject.json` 과 `keywords.json` 뿐이다.
`docs/NEW_SUBJECT.md` 를 따른다.

### 국어·수학·영어
판형이 근본적으로 다르다. `docs/LAYOUTS.md` 를 읽고 어댑터를 만들어야 한다.
**이 저장소는 그 어댑터를 아직 갖고 있지 않다.** 사용자에게 솔직히 말하고 함께 만든다.
